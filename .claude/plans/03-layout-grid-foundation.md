# 12列レイアウトグリッドの基盤ルール導入

## Context

Issue #81(「/」区切り禁止)への対応として `SpecList` コンポーネントを実装したPR #83をユーザーが却下した。却下理由(原文):

> あまり良い修正ではありません。
> 項目名と値の区別はまだみにくいままです。また、視線を主に横に動かす必要があり、縦スクロールとの相性が悪い配置です。
> このPRはマージせずクローズして一度根本的な見直しを図ります。
> Issueはオープンなままにしておいてください。
>
> ページ全体を12列前後のGrid（repeat 1fr）に分割し、原則このGridに沿うように要素を配置するように、新たにIssueを作成してください。明確な意図がある場合はこのGridからはみ出すことを許容しますが、理由を都度記載してください。

この指示に基づき Issue #84(ページ全体を12列前後のGridで構成するレイアウト基盤ルールを導入する)を起票済み。Issue #81 は、この12列グリッド導入後にあらためて解決策を設計し直す想定でオープンのまま維持されている(Issue #84 が #81 より先行する上位の設計判断)。

このPRは、これまでの3ステップの流れ(1. 現状確認・Issue起票、2. ルール点検・修正・PR作成、3. 実装修正・PR作成)のうち、Issue #84 に対する「2. ルール点検・修正」にあたる。個別ビューへの適用(Issue #81 の再設計)は別PRで行う。

## 現状の構造の確認

`frontend/src/App.vue` を確認したところ、`.app-shell` の直下の子要素は `.app-header` と `.app-main`(`<RouterView />` をラップ)の2つのみ。各ビューの実際のコンテンツ(`RecipeListView.vue` 等)は `<RouterView />` を通じて `.app-main` の子として描画される。CSS Gridは祖先の列トラックをそのまま子孫に伝播しない(subgridなしでは)ため、「ページ全体」を単一のgridツリーで表現することはできず、12列グリッドは**各コンテナが個別に採用する再利用可能なユーティリティ**として設計する必要がある。

## approach

- `frontend/src/style.css` に `.grid-12` ユーティリティクラスを新規追加する:
  ```css
  .grid-12 {
    display: grid;
    grid-template-columns: repeat(12, 1fr);
    gap: 0 1rem;
  }

  .grid-12 > * {
    grid-column: 1 / -1;
  }
  ```
  - 12列を選んだ理由: 2/3/4/6で割り切れ、`span 6`(半分)`span 4`(3分割)`span 3`(4分割)など柔軟な組み合わせが可能(業界的にも一般的な列数)。
  - 直下の要素はデフォルトで12列すべてに広がる(`grid-column: 1 / -1`)。既存の縦積みレイアウトと視覚的に変わらない(既存ページの見た目を壊さない)。部分的な列幅で配置したい要素だけが `grid-column: span N` 等を明示指定する、というのが「原則グリッドに沿う、逸脱時は理由を明記する」というユーザー指示の技術的な実装形。
  - ガター値は既存の `.form-grid` と同じ `gap: 0 1rem`(横1remのみ、縦方向は各要素自身のマージンに委ねる)を踏襲し、新しい間隔値を増やさない。
- `frontend/src/App.vue` の `.app-shell` に `grid-12` クラスを組み合わせる(`class="app-shell grid-12"`)。`.app-header`/`.app-main` はデフォルトのまま12列全体に広がるため、視覚的な変化はない。
- `docs/design-system.md` に新しい「10. レイアウトグリッド」節を追加し、上記のルールと設計意図を明文化する。あわせて:
  - 6節(レスポンシブパターン)から新節への参照を追記。
  - 8節(新規UIパターン追加時のガイドライン)に10番目の検討項目として「レイアウトグリッド」を追加(既存の1〜9番の番号は変更しない)。
  - 既存の `.form-grid`・`.step-row`・`.card-list` は当面そのまま維持し、12列グリッドへの統合要否は実際に置き換える段階のPR(Issue #81の再設計を含む)で個別判断する旨を明記する。

### スコープ外

- `.form-grid`・`.step-row` を12列グリッドの `span` ベースに置き換えること(Issue #84の「今後の対応方針」に記載の通り、実際に手を入れる段階で判断)。
- Issue #81(「/」区切り表示)の再設計そのもの。このルール確立後に別PRで着手する。

- `cd frontend && npm run fmt:check && npm run lint`
